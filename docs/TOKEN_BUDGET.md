# Как выбраны бюджеты генерации

Денежный лимит ключа, cap одного ответа, контекст модели, число запросов и wall-time — независимые ограничения.
600 RUB в сутки на команду не сообщают число доступных токенов без тарифа входа/выхода, кэша и единицы
стоимости в ответах прокси. Каркас не переводит provider usage.cost в рубли по предположению.

## Наблюдения и границы вывода

Аудит предоставленного запуска от 21 октября 2026 года: 13 попыток/ответов; 48 132 сообщённых выходных
токена, 190 763 входных и 68 864 cached input. Три ответа обрезаны: один finish_reason=length без
итогового content и два tool_calls с незавершёнными JSON-аргументами на cap=8192.
Медиана выходных токенов среди необрезанных ответов — 1900, но она смешивает bootstrap, инструменты и
финальные ответы. Это не обоснование малого лимита исследователю. У оборванных ответов истинная длина
неизвестна: точный достаточный cap или честный p95 по этим данным вычислить нельзя.

Поэтому применена проверяемая стартовая политика, а не обещание достаточности:

| Настройка | Default | Назначение |
|---|---:|---|
| LLM_BOOTSTRAP_OUTPUT_TOKENS | 4096 | Интерпретация условия и план валидации; при обрыве тоже повышается |
| LLM_MAX_OUTPUT_TOKENS | 16384 | Исследовательский ответ: следующий двоичный уровень после оборванных 8192 |
| LLM_MAX_OUTPUT_TOKENS_LIMIT | 32768 | Верхняя клиентская граница удвоения |
| LLM_MAX_TOTAL_OUTPUT_TOKENS | 262144 | Консервативная квота output на один запуск |
| LLM_MAX_CALLS | 32 | Общая граница API-попыток |
| LLM_TIMEOUT_SECONDS | 600 | HTTP timeout одной попытки |
| LLM_OPERATION_TIMEOUT_SECONDS | 1200 | Один весь диалог, включая очередь и повторы |

Допустимые provider context/output limits не были live-проверены здесь. Клиентские значения можно
настроить; отказ прокси из-за неподдерживаемого запроса должен быть виден явно. SDK HTTP timeout —
ограничение сетевой операции, не принудительная остановка Python-потока по таймеру. Перед каждой
попыткой timeout ограничивается остатком операции и общего запуска; крошечный новый запрос не запускается.

## Распределение и учёт

Стартовая программа поиска: ранний baseline + до 4 catalogue warmups + до 8 LLM-планов, всего до 12
новых обучений после baseline. Warmups не используют LLM. Две bootstrap-попытки по 4096 и восемь
исследовательских по 16384 дают потолок 139 264 токена для этого простого сценария. Ещё две отдельные
repair-попытки по 32768 дают 204 800 суммарно, что помещается в 262 144. Это пример резервирования,
не прогноз расхода: повторов/ошибок может быть больше, а фактический ответ часто короче лимита.

Перед каждым API-вызовом Budget атомарно резервирует max_tokens. После ответа резервация заменяется
фактическим completion_tokens. При таймауте/отсутствии usage весь резерв списывается в output_charged;
в output_reported попадает только реально сообщённое значение. Поэтому charged может быть выше reported.
Это ограничивает повторные неизвестные расходы и предотвращает overcommit двумя исследователями.

Если квоты не хватает, новые API-попытки останавливаются; последний проверенный CSV сохраняется.
Квота output не является денежной защитой от всех расходов: входные токены также оплачиваются по
правилам провайдера, а ключ общий с другими участниками. Серверный Budget has been exceeded остаётся
окончательным сигналом остановки, без ожидания суточного сброса внутри задачи.

## Сокращение ненужной генерации

По умолчанию ResearchChoice-v1 содержит только recipe_id, hyperparameters, hypothesis, expected_effect.
Код создаётся из проверенной factory-функции. Нет цикла «написать код → write_code → повторить код в JSON».
Для нестандартного Python явно включается RESEARCH_MODE=code; это отдельная стоимость/граница надёжности.
Никакие не подтверждённые прокси параметры отключения reasoning не отправляются.

Проверить новые/старые журналы без повторного API-запроса:

```bash
python scripts/analyze_run.py runs/ИМЯ_ЗАПУСКА
python scripts/analyze_run.py /path/to/run.zip --json
```

Токены reasoning провайдер иногда сообщает больше completion_tokens. Каркас сохраняет оба значения и
ставит usage_inconsistent, не подгоняя числа. Текст скрытых рассуждений не восстанавливается.
