# Проверка поставки v0.1.0

Дата: **21 октября 2026 года**. Входы проверки — только синтетические задачи генератора. CSV из приложенного архива хакатона не использовались.

## Выполнено

`python scripts/check.py`: **45 тестов, OK**, 49.883 секунды в среде подготовки.

- Проверены 81 JSON fixture согласованных контрактов, запрет лишних полей и non-finite JSON.
- Проверены точная дедупликация, конкурентная идемпотентность, повтор и устаревший job event, направление метрик и сравнимость протоколов.
- Проверены публикация, порядок и ведущие нули id, изменение файла после проверки, запоздавший худший кандидат, конфликт версии, одинаковый CSV разных кандидатов и восстановление journal после replace до SQLite commit.
- Проверены Native tool-call/response-проводка через FakeTransport, ограниченное исправление JSON и отсутствие retry при HTTP 401. Сеть для этого не использовалась.
- Проверены маскирование ключей, отсутствие API-ключа в training env, неоднозначность путей, literal NA и duplicate CSV header, ограниченный LLM-профиль.
- Проверены отмена родителя и дочернего процесса, реальный таймаут с C24 → C15 → C13 release, worker-side memory watchdog и ошибка запуска процесса без утечки lease.
- Пройдены полные subprocess-запуски классификации, регрессии и бинарной задачи. Выходной CSV валиден; лучшие модели в двух первых сценариях улучшили локальную метрику относительно Dummy.
- Пройдены отказ LLM после baseline и искусственное сокращение бюджета после публикации: готовый CSV сохранён.
- Пройден запуск из распакованного платформенного ZIP, из другого cwd, без зависимости от исходного пути репозитория.
- Проверены групповой holdout и разделение полных временных периодов.

Полный вывод unittest: `validation-unittest.log`.

## Следующий внешний прогон команды

1. Установить requirements.txt в чистую Python 3.12 среду или собрать Dockerfile.
2. Запустить scripts/doctor.py и scripts/check.py на точных версиях.
3. Подключить значения OPENAI_* организаторов и проверить один небольшой live-запуск, включая JSON/tool-call формат конкретного сервиса.
4. Проверить CatBoost-рецепт и интерфейс официального контейнера.
5. После этого отправлять dist/solution.zip на платформу с учётом лимита сабмитов.

Live API, точный Docker-образ платформы и CatBoost фактически не запускались: ключ/endpoint отсутствуют, пакеты не установлены. Приложенный Dockerfile — подготовленная конфигурация локального прогона, а не утверждение о выполненной Docker-сборке. Это рабочий каркас для развития командой, не заявление о готовом соревновательном качестве.
