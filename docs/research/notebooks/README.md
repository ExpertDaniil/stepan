# Локальные исходные тетради: первые два оригинала

Здесь сохранён код, а не только ссылки. Это **два исходных файла одной авторской
подборки OSIC**, а не два независимых победных решения и не законченная
разнообразная библиотека. Подготовка выполнена после архитектуры и руководства.

| Файл | Что действительно внутри | Что можно изучать |
|---|---|---|
| [simple-logreg.ipynb](osic-artkulak/simple-logreg.ipynb) | Девять кодовых ячеек; несмотря на имя, используется `LinearRegression`, а не логистическая регрессия. Пояснения даны комментариями | Формирование пар «исходное наблюдение → будущий момент», разность времени, линейная отправная модель |
| [inference-45-55-600-epochs-tuned-effnet-b5-30-ep.ipynb](osic-artkulak/inference-45-55-600-epochs-tuned-effnet-b5-30-ep.ipynb) | 53 ячейки с разделами Markdown; обработка снимков, квантильная регрессия и смесь предсказаний | Признаки относительно исходного наблюдения, функция потерь для нескольких квантилей, согласование предсказаний по ключу |

Оба файла скопированы **без изменения байтов** из
[авторского репозитория Art Kulakov](https://github.com/artkulak/osic-pulmonary-fibrosis-progression)
на закреплённом состоянии `cd6dfa56c012e3c0eb81ed15534f436b3ba16d19`.
Разрешение на распространение находится в исходной [LICENSE](osic-artkulak/LICENSE)
(`Unlicense`). Адреса, размеры и контрольные суммы записаны в
[provenance.json](osic-artkulak/provenance.json). Исторические выводы ячеек
оставлены как часть оригинального файла; они не являются результатами запуска
этого проекта.

Тетради не выполнялись. Наборы данных, снимки, веса и устанавливаемые пакеты не
скачивались. Ни одна сохранённая оценка исходного автора не подтверждена нашим
обучением. Первое место относится к составному решению автора; его README
отдельно называет `simple-logreg` простым подходом, а не победным решением.

## Как выбирать конкретный фрагмент

[index.json](index.json) отделяет исходник от нашей разметки. У каждого приёма
указаны смысловые роли признаков, необходимые входы, способ проверки, выбранные
ячейки и контекст, библиотеки и ограничения. `cell_indices` нумеруются с нуля
по массиву `cells` исходного файла. Выборка ячеек — материал для исследования,
а не поручение выполнить их.

В режиме `RESEARCH_MODE=adaptive` подборка подключена к исследователю через
`consult_notebook`. Подключение создаёт [runtime](../../../agent/runtime.py),
доступные операции описывает [ResearchTools](../../../agent/research_tools.py),
а поиск и чтение выполняет [NotebookLibrary](../../../tools/notebooks.py).
Доступа к внешним сайтам при этом нет. Прежние режимы `catalog`/`code` этим
инструментом не пользуются.

Первый запрос возвращает до двух карточек приёмов с условиями применения:

```json
{"kind":"search","keywords":["baseline"],"offset":0,"limit":2}
```

`next_offset` позволяет прочитать следующую страницу. Пустой список `keywords`
показывает все имеющиеся приёмы по страницам. Поиск ранжирует совпадения слов,
тип задачи и подсказки имён столбцов, но не прячет приём из-за несовпадения типа
задачи. Поле `semantic_roles_confirmed=false` прямо показывает: совпадения
названий недостаточно, смысл признаков ещё нужно установить по текущему условию
и проверяемым фактам.

Например, при повторных наблюдениях одного объекта сначала нужно установить,
доступно ли его исходное значение целевой величины в момент прогноза. Затем
можно прочитать приём `osic-relative-baseline` и его исходный код:

```json
{"kind":"read","approach_id":"osic-relative-baseline","cell_index":25,"offset":0,"max_chars":5000}
```

Один вызов читает одну размеченную ячейку или её фрагмент, максимум 5000
символов. Длинная ячейка возвращает `next_offset`: следующий запрос с этим
смещением продолжает её без потери остального текста. Для примера выше
`cell_indices` разрешают ячейки 25–27, а `context_cell_indices` — 22, 23 и 30.
Контекст читается отдельными такими же запросами; целая тетрадь в ответ модели
не передаётся. Здесь показаны реальные формы запросов средства, а не обещание,
что живая модель обязательно выберет именно эту последовательность.

Ответ сопровождается условиями, требованиями к проверке и рисками. Перед
чтением проверяется SHA-256 оригинала; выводы выполненных когда-то ячеек не
выдаются. Поля `execution_performed=false` и `material_status` отделяют
учебный материал от исполняемого поручения. Применимость выясняет исследователь:
если исходного уровня объекта в задаче нет, этот приём использовать нельзя.

Каждый ответ сохраняется в `research/references-*.json` каталога запуска с
типом `notebook_excerpt`. Этот идентификатор не принимается в `evidence_ids`
как измерение текущей задачи. Исследователь может изучить приём, предложить
собственный допустимый опыт и затем сослаться на его настоящую оценку или
дополнительный отчёт анализа данных.

## Поставка и отказ чтения

[package_solution.py](../../../scripts/package_solution.py) явно включает пять
текстовых ресурсов: `index.json`, `provenance.json`, `LICENSE` и две исходные
тетради. В плоском платформенном ZIP они находятся читаемым текстом в
`stepan_resources.py`; при запуске восстанавливаются в локальные файлы.
Модуль `tools/notebooks.py` поставляется отдельным читаемым Python-модулем.
Установка пакетов и выполнение исходных ячеек не происходят.

Если подборку нельзя подключить при подготовке запуска, появляется событие
`research.references_unavailable`; необязательный источник примеров не должен
помешать первому проверенному ответу. Запрос неизвестного приёма или
неразмеченной ячейки получает предметную ошибку. Изменение байтов оригинала
возвращает `NOTEBOOK_SOURCE_CHANGED`, а не незаметно новую версию примера.
Причина и материалы вызова сохраняются обычной трассировкой запросов.

Исходные методы всё ещё нужно переносить в допустимый обучаемый конвейер и
проверять на текущем протоколе. Подключение локального чтения не превращает
старый код в совместимое с нашим запуском решение.

## Почему оригиналы нельзя копировать как готовые конвейеры

- `simple-logreg`, ячейка 2: недели перебираются через `iloc[1:]`, а значение
  FVC берётся через `iloc[i, 2]`. Перед переносом необходимо проверить
  соответствие момента и цели, порядок строк и отказаться от позиционных
  номеров столбцов. Настоящей проверки по независимым пациентам в тетради нет.
- Вторая тетрадь содержит установку пакетов, TensorFlow/Keras, EfficientNet,
  медицинские снимки и обращения к локальным весам. Это не разрешённый способ
  выполнения текущего AutoML. Указание тяжести в разметке — качественная
  оценка по коду; длительность не измерена.
- Ячейки 23–30 объединяют части данных перед некоторыми преобразованиями;
  ячейка 35 использует обычный `KFold` по строкам. Для переноса на повторные
  объекты необходимо заново организовать проверку по группам и обучать
  преобразования внутри обучающей части.
- В оригинале встречается устаревший `DataFrame.append`; современная среда
  проекта не означает автоматической совместимости старого кода.
- Входные файлы, целевые столбцы и медицинская функция качества исходника не
  заменяют условие текущей задачи. Ячейки сохранены для изучения приёма,
  а не для подмены независимого оценщика.

Это собственные результаты чтения кода. Исправленная адаптация под проект не
создавалась и под видом оригинала не публикуется.
