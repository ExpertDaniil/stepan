# Поставка и запуск после уточнения инструкции

Источник требований: предоставленная 21 октября 2026 года «AutoML_Инструкция по ключам.md.pdf», страницы 1–3. Уточнение формата ZIP имеет приоритет над прежними предположениями схемы v0.1. Таблицы хакатона для этого обновления не читались.

## Контракт запуска

Платформа копирует в каталог **одной** задачи только корневые `.py` и `requirements.txt` из загруженного архива. Затем запускает:

```bash
python3 solution.py task.md
```

Рабочий каталог содержит её условие и данные. Путь к условию приходит через CLI; агент не скачивает задачи и не опрашивает очередь. `submission.csv` должен появиться рядом с `task.md` по схеме условия. Промежуточные подкаталоги в каталоге задачи и `/tmp` разрешены. Ресурсы: 8 CPU, 32 GB RAM, до 3 часов на задачу; ZIP до 100 MB.

Локально передавайте путь к конкретному условию, например:

```bash
python3 scripts/list_tasks.py data_for_participants
python3 solution.py "data_for_participants/Регрессия/task.md" --env-file .env
```

`list_tasks.py` проверяет пути, не содержимое CSV и не качество задачи. Он не требует API-ключа. Ошибка `AMBIGUOUS_PATH` означает несколько подходящих файлов в выбранной области; нужно выбрать условие одной задачи, а не объединять данные разных задач.

## Содержимое submission ZIP

`python3 scripts/package_solution.py` генерирует `dist/solution.zip` с читаемыми исходниками. Все элементы лежат в корне:

| Файл в корне ZIP | Содержимое |
|---|---|
| solution.py | Небольшая точка входа: копирование соседних исходников в package-каталоги `/tmp` и вызов `agent.runtime.main` |
| requirements.txt | Побайтовая копия предоставленного списка зависимостей |
| agent_runtime.py, agent_orchestrator.py, agent_graph_controller.py и остальные agent_*.py | Отдельные исходники `agent/`, побайтово сохранённые из Git |
| tools_code.py, tools_data.py, tools_files.py, tools_init.py | Отдельные исходники `tools/` |
| stepan_resources.py | Открытые строковые литералы SQL-схем, JSON-контрактов/рецептов и Markdown-промптов |

Исходный модульный `solution.py` в Git служит для разработки и импортирует `agent/`. Сборщик генерирует отдельную точку входа для платформы. Она содержит явное соответствие имён: например, `agent_graph_service.py` копируется в `agent/graph/service.py`. Изменения импортов или исходного кода модулей не требуются. Код можно прочитать сразу после открытия ZIP. В `solution.py` нет base64/base85, сжатого кода, встроенного архива или исполнения декодированных строк.

При старте исходники копируются в приватный временный каталог `/tmp`, а текстовые ресурсы записываются из `stepan_resources.py`. Затем вызывается тот же `agent.runtime.main`. Subprocess обучения получают этот путь, работают до завершения, затем временный runtime удаляется. Таймер запуска начинается до копирования, чтения ресурсов и тяжёлых импортов.

Поставляются только наши `.py` и открытые текстовые ресурсы. Сторонние пакеты, `.whl`, реальные CSV, веса, секреты и журналы в ZIP не входят. Сборщик использует allowlist, запрещает symlink, проверяет коллизии плоских имён, точные requirements, синтаксис Python, плоский состав и лимит 100 000 000 байт. Результат заменяется атомарно только после проверки. Библиотеки во время решения не устанавливаются.

Для локального чтения исследовательских материалов `RESOURCE_FILES` отдельно включает пять текстовых файлов:
`docs/research/notebooks/index.json`, `osic-artkulak/provenance.json`, `osic-artkulak/LICENSE` и два исходных
`.ipynb` той же папки. Их байты представлены открытым текстом в `stepan_resources.py` и восстанавливаются
по явным относительным путям временного каталога. Это тетради для чтения через `consult_notebook`,
а не код, который запускается при распаковке. Лицензия оригиналов — `Unlicense`, контрольные суммы
и происхождение находятся в [описании подборки](research/notebooks/README.md).
Инструмент отдаёт выбранную ячейку без её исторического вывода и не обращается к внешним сайтам.

Кроме этих пяти файлов в `stepan_resources.py` включены шесть ресурсов `recipes/knowledge`:
`manifest.json`, `cards.json`, `competitions.json`, `sources.jsonl`, `selection.json` и `UPSTREAM_LICENSE.txt`.
Это отдельная текстовая библиотека и собственные примеры проекта; её 154 разбора не выдаются за
оригинальные `.ipynb`. Подготовка корпуса выполняется заранее. На платформе не нужны исходный архив,
`scripts/prepare_knowledge.py`, сеть или новая модель поиска. Содержимое возвращается как изучаемый
материал через `search_knowledge`; подробности и происхождение — [KNOWLEDGE.md](KNOWLEDGE.md).

`requirements.runtime.txt` — разрешённое подмножество для быстрой локальной среды и Dockerfile. `requirements.txt`/`requirements.organizers.txt` сохраняют полный предоставленный список. Это не утверждение, что полный список зависимостей был успешно установлен в среде подготовки: фактические ограничения проверки указаны в `VALIDATION.md`.

## Подключение модели

| Настройка | Правило |
|---|---|
| OPENAI_API_KEY | Обязателен; выдаётся команде, на платформе подставляется в env |
| OPENAI_BASE_URL | Обязателен; на платформе используется только выданный ею адрес |
| OPENAI_MODEL | Необязателен; default qwen/qwen3.8-27b, прокси выбирает модель задачи |
| Маршрут | OpenAI SDK вызывает `{OPENAI_BASE_URL}/chat/completions` |
| Общий бюджет ключа | 600 RUB в сутки на команду; сброс 03:00 МСК |

Для локальной среды инструкция приводит основной `https://changellenge.up.railway.app/v1` и запасной `https://api.alfahack-gateway26.ru/v1`. Адрес выбирается командой в `.env`, не меняется автоматически. В коде нет default для адреса/ключа. `.env` читается только с `--env-file`; стандартные env платформы имеют приоритет.

При серверном сообщении `Budget has been exceeded` Gateway выставляет общий флаг для двух исследовательских контекстов, пишет `llm.call_failed` и `llm.daily_budget_exhausted` и не повторяет запросы. Уже начатый параллельный API-запрос может завершиться отдельно. Часы до сброса не ожидаются; сохранённый проверенный baseline используется как результат. Обычный временный HTTP 429 сохраняет ограниченные retry. Стоимость в рублях из токенов не придумывается.

Ответ `Insufficient credits`, в том числе внутри HTTP 503 от LiteLLM/OpenRouter, обрабатывается
отдельно: `LLM_PROVIDER_CREDITS_EXHAUSTED`, `retryable=false`, дальнейшие вызовы в этом запуске
блокируются. Это сообщение внешнего провайдера; время сброса и остаток командных 600 RUB из него
не выводятся. Если отказ пришёл до интерпретации задачи/первого CSV, запуск завершается с ошибкой.
Восстановить доступ должен оператор предоставленного API. Ошибка обычного временного 503 без
этого маркера по-прежнему допускает ограниченные повторы.

## Что проверяет тест платформенного запуска

Тест собирает ZIP, копирует **только** корневые `.py` и `requirements.txt` к синтетическому `task.md`, убирает исходный PYTHONPATH и запускает ровно `python solution.py task.md` из каталога задачи. Отдельно проверяются классификация и регрессия. Затем проходят baseline, исследователи, subprocess обучения, оценка, refit и публикация CSV. Дополнительная проверка сравнивает каждый Python-модуль с исходником Git, а каждый текстовый ресурс — с исходным файлом. Это проверка документированного механизма копирования; загрузка в сам Boosters и live API здесь не выполнялись.
