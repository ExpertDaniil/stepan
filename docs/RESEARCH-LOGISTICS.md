# Исправление исследовательского интерфейса

Разбор запуска 2d0247b8 показал конфликт схемы pipeline/tuning, повторные ошибки
адресации памяти, потерю финального ответа на 360-секундной границе и фактически
один фоновый worker с шестью потоками. Исправления универсальны для задач и метрик;
данные, целевые столбцы и код из реального запуска в репозиторий не включены.

## Короткий путь к исполняемому решению

В executable-режиме у C10 есть read_solution с контрактом SolutionRead:

```json
{"experiment_id":"best"}
```

Он возвращает выбранный ID, код, эффективные параметры, feature_steps и независимую
метрику. Для компактного чтения есть view=code/result/features/diagnostics. Можно
передать конкретный experiment_id. Длинные ответы имеют next_read с точным ID,
view и UTF-8 offset: смена лидера не меняет источник продолжаемой страницы.

Выбор best ограничен текущей веткой, задачей и validation. API thread читает
неизменяемый scoped snapshot C08 и уже авторизованные dispatcher updates, без SQL.
Dispatcher добавляет планы/ссылки на hash-checked код в solution_catalog; wire
projection удаляет этот каталог и оставляет best_solution. Свежий каталог доступен
по инструменту даже для результата, появившегося после начала диалога. Подробный
контекст содержит research_incumbent; assignment base остаётся ссылкой lineage,
а не ложным обещанием, что эта модель — текущий лидер.

read_memory остаётся для определения задачи, исследовательских записей и анализов.
section=detail_index теперь действительно читается. Ошибка неизвестного раздела
возвращает допустимые разделы данного документа, reference контекста и подсказку
читать решения через read_solution. Соседняя ветка и произвольный artifact недоступны.

## Одна схема предложения

Для pipeline схема рекламирует tuning=null; диапазоны задаются literal SEARCH_SPACE.
Совместимость с прежними ответами: tuning.search_space механически переносится в
SEARCH_SPACE, если его ещё нет. Совпадающая декларация сохраняется; конфликтующие
диапазоны отклоняются с конкретной ошибкой. max_trials и budget_seconds из старого
tuning не управляют исполнением: бюджет принадлежит фоновому сервису. Код не
исполняется при нормализации. Преобразование повторяемо и не ломает future imports.

Параметр base_recipe_id в произвольном исходнике не превращает его в наш wrapper.
Вложенный поиск model_parameters выбирается только для точного owned feature factory.
Старый валидатор различает отсутствие кода, неверный recipe и недопустимый tuning.
Проверки исполнения, независимая оценка, политика кода и защита CSV сохраняются.

## Время и ресурсы

Default диалога — 900 секунд, поверх него действуют operation deadline и резерв
публикации. Явные значения .env сохраняются. Перед tool-фазой фиксируется окно
финального ответа: по оценке времени модели, минимум 25% и максимум 45% доступного
диалога (для очень короткого окна — не более 45%). HTTP timeout и ожидание API slot
для инструментальных ходов заканчиваются до него. Таймаут инструментария закрывает
tool-фазу и оставляет финальный запрос; provider outage всё ещё может помешать ответу.

Очередь Python-анализа, чтение данных и процесс анализа получают ту же временную
границу. Сохранённые отчёты остаются доступны. После запроса его deadline удаляется
из рабочего состояния сервиса; следующий анализ не наследует истёкшее окно.
Операции над ограниченной pandas-выборкой имеют кооперативные проверки времени.

Для двух фоновых workers заранее выделяется по три потока при общей ёмкости
семь и резерве одного потока для анализа. Память делится с сохранением резерва
анализа. MAX_WORKERS=1 допускает до шести потоков. Это меняет параллелизм, не
доказывает ускорение на любой модели; для него нужен полноценный benchmark.

## Проверка

Точечные регрессии проверяют нормализацию прежнего формата, scoped/latest reads,
работу native tool в gateway, UTF-8 страницы, hashes и резерв времени после timeout.
Отдельно перепроверены пять сохранённых ответов Qwen: все проходят executable
validation после исправления. Это не результат обучения этих программ.
Короткие scripted-прогоны используют настоящее fit/evaluate/refit и CSV для обеих
задач; полная suite и live-Qwen запуск не выполняются по указанию пользователя.
Фактические результаты: [validation-research-logistics.json](validation-research-logistics.json).
