# 10. Листья: простая модель и специалист по путаемым классам

**MLE-bench:** `leaf-classification`. **Задача:** вид листа, многоклассовая логарифмическая потеря. **Вход:** небольшая таблица из 192 готовых описателей и изображения. Формально это соревнование изображений, но полезная для нас часть работает с таблицей. **Приоритет:** высокий для малой выборки с большим числом классов.

## Два первоисточника

1. **LEAF-1 — Ivan Sosnovik, [интервью победителя Kaggle](https://medium.com/kaggle-blog/leaf-classification-competition-1st-place-winners-interview-ivan-sosnovik-d1bf7111c055).** Прочитано интервью первого места. Логистическая регрессия дополнена случайным лесом для нескольких путаемых групп классов. Победный набор признаков включал и новые характеристики изображений: выдавать его за решение только на исходных 192 столбцах нельзя. Автор также использовал рискованные пороги, подбирая их по оценке на всей исходной проверке; эту часть не переносим.
2. **LEAF-2 — Ivan Sosnovik, [комментарии в Computer Vision News, май 2017, стр. 12–13](https://www.rsipvision.com/ComputerVisionNews-2017May/files/assets/common/downloads/Computer%20Vision%20News.pdf).** Прочитаны авторские комментарии. После соревнования автор сравнил подход с нейросетью по изображениям и табличным признакам; на этой малой выборке ручные признаки с простой моделью оказались сильнее. Это вторая первичная публикация того же победителя, не независимое подтверждение эффекта.

## Приём: простая модель — полноценный кандидат на малых данных

**Если:** объектов мало относительно числа признаков, классов много, готовые описатели информативны. **Адаптация для нас:**

1. Проверить стандартизацию и регуляризованную логистическую регрессию; сравнить с бустингом на одинаковых разбиениях.
2. При избыточности признаков проверить PCA, обучая её только внутри обучения. Выбор числа компонент — также часть обучения.
3. Для логарифмической потери сохранять вероятности всех требуемых классов и их правильный порядок. Размерность и набор меток брать из текущей задачи, не фиксировать 99 классов.
4. При совсем редких классах число частей проверки ограничить их представленностью. Не строить разбиение, в котором модель вообще не видит один из оцениваемых классов.

## Приём: специалист для устойчиво путаемой группы

Матрицу ошибок получить по прогнозам вне обучения соответствующих строк. Найти небольшую устойчивую группу классов и обучить для неё отдельный случайный лес либо другую компактную модель. Порог направления к специалисту выбирать на обучающих разбиениях, а пользу проверять на независимой части.

**Наш предлагаемый вариант с сохранением вероятностей:** пусть C — группа классов, `m = sum(p[c] for c in C)` — её суммарная вероятность общей модели, `q` — нормированные вероятности специалиста. На выбранных строках положить `p_new[c] = m*q[c]` для C, а остальные вероятности сохранить. Проверить нормировку и защиту от нулей. Это инженерная адаптация, не формула из интервью.

Сравнить общую модель, обычную смесь и специалиста. Если группа или порог нестабильны между разбиениями, простой вариант предпочтительнее. Нельзя выбирать путаемые классы по известным правильным ответам окончательной проверки.

## Перенос к нам

- Табличный вариант использует только готовые столбцы. Изображения, OpenCV, новые контуры/моменты и чужие веса не нужны. Если условие не выдаёт изображения, сведения об их размерах недоступны.
- scikit-learn и NumPy разрешены. Малый размер выборки делает эти методы доступными на процессоре, но конкретное время зависит от задачи.
- Окончательный результат победителя не служит обещанием почти нулевой потери на наших данных. Жёсткое обнуление «маловероятных» классов способно резко ухудшить эту метрику.

**Первый опыт:** до 15 минут на логистическую регрессию и разбор устойчивых ошибок; затем один небольшой специалист. Зафиксировать логарифмическую потерю всей выборки и спорной группы, качество нормировки вероятностей и чувствительность результата к разбиению.
