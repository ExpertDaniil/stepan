# Stepan: открытый исследовательский цикл

Ветка: `feat/final-data-research`. Основа — `07f22e2`; сохранены последующие
коммиты команды `b84db1f`, `1c8b3b4`, `ba9ab41`, включая идентичность исходника
при расчёте времени custom pipeline и проверки совместимости старых контекстов.

## Что реализовано

| Пункт плана | Изменение |
|---|---|
| 1. Платформенные границы | Согласованы producer/schema/consumer; строгие GResearchContext и GContextUser проверяются также внутри плоского ZIP. Историческая причина нуля без исходного архива и traceback не объявляется воспроизведённой. |
| 2. Надёжный результат | Сохраняется проверенный CSV; ключи финализации учитывают версию чемпиона; joblib использует потоки в пределах lease. Первые обучаемые pilots ограничены по размеру и начинаются с ExtraTrees/HGB. |
| 3. Контекст | Полное состояние сохраняется до сокращения. Большие код и параметры читаются по ссылке; дубли удаляются. Контракт задачи, ограничения и карта входов остаются доступны. Лимиты реальных HTTP bytes не повышены. |
| 4. Решения и исправления | В compact research-v2 нужна одна investigation вместо нескольких обязательных записей. Технические defaults добавляет код. Проверки ссылок, параметров, Python, признаков и tuning-space возвращаются в repair-диалог. |
| 5. Продолжение исследования | research/continue сохраняет ход без обучения; wait/finish закрывают поручение. Новые измерения и отличающиеся вычисления анализа дают основание продолжать. Пустые повторы приостанавливаются. |
| 6. Python-анализ | run_analysis выполняет код в отдельном процессе на fit-only выборке, возвращает отчёт/traceback, кэширует одинаковые вычисления. API-ключи и holdout-метки процессу не передаются. |
| 7. Исполняемая история | Сохраняются родители, точный SHA-256 кода, dataset/validation и независимо рассчитанные результаты. Аналитическая запись не получает выдуманную метрику модели. |
| 8. Смысловая память | Определения, наблюдения, гипотезы и конфликты разделены. Проверенные по структуре поправки применяются к временной смысловой модели до проверки зависимого преобразования. Истинность интерпретации не сертифицируется. |
| 9. Координация | Сохранены общая очередь, свежие результаты, контроль пересекающихся серий и дедупликация. Аналитические операции теперь учитываются при определении прогресса. |
| 10. Практический опыт | Существующие офлайн-карточки и примеры кода сохранены; поиск учитывает текущий исследовательский вопрос. Дополнительная embedding-модель или загрузки из сети не требуются. |
| 11. Допуск экспериментов | Совместные изменения признаков, обработки и модели разрешены. Действуют ограничения стоимости, ресурсов и доказательств; обязательное 30-минутное окно по умолчанию отключено. |
| 12. Проверка | Полная suite, повторяемая проверка ZIP на обеих задачах, публичные данные и короткое сравнение четырёх режимов. Разные уровни доказательств указаны отдельно. |

При переполнении tool-диалога после сокращения создаётся автоматический checkpoint
контроллера. Он сохраняет полученные отчёты и продолжает работу новым диалогом;
это явно не обозначается как решение или объяснение Qwen. Старые записи без
доступного output-артефакта получают происхождение unknown_legacy.

## Проверки итоговой версии

**489/489 тестов**, без пропусков и ошибок; 404.840 с (`scripts/check.py --jobs 3`).

Проверки после объединения: 59/59; смысловая память и совместимость происхождения: 55/55; статическая проверка официальных зависимостей и схем — пройдена.

Итоговый ZIP: `stepan-open-research.zip`, 612306 байт. SHA-256:
`33d99ea82f0776d9812e336b5727abc8a643cb5f8f6a3607267c09853b660393`.

Один и тот же ZIP копируется по правилам платформы: только корневые `.py` и точный
официальный `requirements.txt`. Обе синтетические задачи выполняют настоящий
Python-анализ, сохранение вывода без обучения, продолжение анализа, обучение
именованной признаковой программы, независимую оценку, полный refit и проверку CSV.
LLM-ответы здесь scripted; у дочернего процесса нет PYTHONPATH репозитория.

Статическая проверка отдельно сверяет схемы, исходники, ресурсы и побайтовое
совпадение requirements с архивом организаторов. Она не подменяет запуск ZIP.

## Сравнение режимов

Один синтетический повтор, по 120 секунд, одна замороженная сборка для всех условий:

| Режим | Протокол | Python | Локальный RMSE | Итог |
|---|---|---|---:|---|
| A | legacy | нет | 11.2833 | completed, аварийная база |
| B | compact | нет | 2.2781 | completed, обученная конфигурация |
| C | legacy | есть | 11.2833 | completed, аварийная база |
| D | compact | есть | 11.2833 | completed, аварийная база |

Это smoke-проверка, а не устойчивый рейтинг архитектур. За столь короткий бюджет
bootstrap и диалог занимают большую часть времени. Сравнение предшествует последнему
объединению с командой и изменению порядка pilots; точный SHA сборки записан в JSON.
Нужны более длинные повторы, чтобы делать вывод о качестве.

Часть локальных потоковых логов оказалась неполной. Итоговые summary и SQLite
использовались для проверки состояния и оценок; счётчики из неполного лога — нижняя
граница. Скрипт сравнения теперь переживает исчезновение временных файлов и может
восстановить состояние/метрику из итогового summary.

## Запуск

Python 3.12 и официальные зависимости устанавливаются до запуска задачи.
Установка самим решением во время задачи отсутствует. Проверки выполнялись
в отдельном dev-окружении.

```bash
python solution.py /absolute/task.md --env-file /absolute/.env
```

Новые defaults: `RESEARCH_MODE=adaptive`, `RESEARCH_PROTOCOL=compact`,
`PYTHON_ANALYSIS_ENABLED=1`, `DATA_RESEARCH_MIN_SECONDS=0`. Явные значения старого
`.env` по-прежнему имеют приоритет.

```bash
python scripts/check.py --jobs 3
python scripts/package_solution.py --output /tmp/solution.zip
python scripts/verify_submission.py --zip /tmp/solution.zip --directory /tmp/zip-check
python scripts/compare_research.py --task /absolute/task.md --output-dir /tmp/comparison --seconds 600 --modes ABCD --repeats 3 --env-file /absolute/.env
```

## Границы результата

Среда проверки: 8 CPU и 8 GiB RAM; заявленная платформа — 32 GiB. Python AST/audit
проверки не являются OS-песочницей для враждебного кода. Неуменьшаемый обязательный
контракт всё ещё может быть больше конечного окна; такой случай диагностируется
явно. LB-подача и полный трёхчасовой benchmark не выполнялись.
