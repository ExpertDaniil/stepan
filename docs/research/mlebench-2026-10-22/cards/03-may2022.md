# 03. Май 2022: составные строки и ограниченные взаимодействия

**MLE-bench:** `tabular-playground-series-may-2022`. **Задача:** двоичная классификация, ROC AUC. **Вход:** числовые признаки и строка фиксированной длины. **Приоритет:** высокий; задача показывает приёмы, которых не даёт обычный перебор параметров.

## Три первоисточника

1. **MAY-1 — AmbrosM и Laurent Pourchot, [#1 Solution: A Two-Branch Network](https://www.kaggle.com/competitions/tabular-playground-series-may-2022/writeups/the-team-1-solution-a-two-branch-network).** Прочитан авторский разбор первого места. Граф обнаруженных взаимодействий разделился на две группы. Две ветви нейросети ограничили нежелательные связи между группами. Аналогичные ограничения улучшили LightGBM, но деревья не вошли в окончательную смесь.
2. **MAY-2 — AmbrosM, [Engineering the top three feature interactions](https://www.kaggle.com/competitions/tabular-playground-series-may-2022/discussion/323892).** Прочитаны текст, формулы и ответы автора. Из парных проекций получены суммы признаков и трёхзначные признаки областей с разными частотами классов. Это объяснение построения признаков тем же победителем, не независимое решение.
3. **MAY-3 — Christophe Nicault, [How to predict the state of a machine?](https://www.christophenicault.com/post/predict_machine_state/).** Прочитана авторская статья с кодом; автор указан восьмым участником в обсуждении MAY-2, оценка опубликованного примера отделяется от итогового места. Строка из десяти символов разобрана по позициям; показаны поиск взаимодействий и небольшая полносвязная сеть. Исходная реализация — R/Keras.

## Приём: отличать составную строку от идентификатора

**Если:** длина строки почти постоянна, позиции имеют небольшие словари и есть смысл раздельных полей. **Адаптация для нас:**

1. Проверить длины, пропуски, алфавит каждой позиции на обучающей части.
2. Получить отдельные категориальные позиции; дополнительно проверить число разных символов. Не присваивать буквам количественный порядок без основания.
3. Сравнить исходную строку, только позиции и их совместное представление. Предусмотреть новые символы и другую длину в проверочных данных.
4. Не делать такой разбор для случайного идентификатора, хеша или свободного текста без дополнительного подтверждения.

## Приём: сначала проверить взаимодействие, затем усложнять модель

На обучающей части выбрать небольшой набор вероятных пар по смыслу и наблюдаемым зависимостям. Проверить суммы, разности или отношения с защитой от нуля; границы областей определять внутри обучения. Оставить только изменения, которые улучшают независимую проверку. Конкретные столбцы и пороги около ±5 из соревнования не переносить.

Если взаимодействия устойчиво распадаются на группы, сравнить обычный LightGBM с ограничением взаимодействий между группами. Альтернатива — компактная двухветвевая сеть на PyTorch, обученная с нуля. Выделение групп и подбор порогов нельзя делать по целевой переменной независимой проверки.

## Перенос к нам

- Достаточно основной CSV; никаких внешних признаков или готового файла взаимодействий.
- Xgbfir из исходного исследования отсутствует в разрешённом списке. Для первого опыта достаточно вручную обоснованных групп; позднее можно анализировать структуру собственных деревьев разрешёнными средствами.
- R/Keras не поставляются. Для переноса признаков нейросеть не требуется; если она нужна, архитектуру переписать на PyTorch без чужих весов.
- AUC считает порядок оценок, но формат ответа всё равно берётся из текущего условия. Не переносить из чужой записи значения за пределами диапазона вероятности.

**Первый опыт:** до 25 минут: исходный CatBoost/LightGBM → позиции строки → несколько обоснованных взаимодействий. Только после прироста проверять ограничения взаимодействий. В отчёте: AUC, количество новых признаков, время, устойчивость на ещё одном разбиении при достаточном размере выборки.
