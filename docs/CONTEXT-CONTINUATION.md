# Продолжение исследования при заполнении контекста

## Подтверждённый сценарий

В предоставленной пользователем выгрузке a3409efb пять исследовательских диалогов
закончились controller checkpoint с CONTEXT_TOO_LARGE. Это локальная проверка
JSON-запроса, а не подтверждённый отказ провайдера по токенам. В одном случае
после сокращения осталось 98 376 байт при лимите 98 304: превышение на 72 байта.
Старый упаковщик сохранял каждую пару вызов/ответ и весь Python в аргументах.
Сокращения тел отчётов не ограничивали рост такого диалога.

## Поведение после изменения

1. Gateway учитывает полный сериализованный запрос, включая схему, инструменты
   и свежую обратную связь. Каждый ход с инструментами сохраняет до 16 КиБ
   свободного места. Ни один запрос не отправляется сверх действующего лимита.
2. Сохраняются прежние сокращения повторяющихся данных. Если их недостаточно,
   завершённые старые tool batches заменяются ограниченной сводкой. Assistant
   tool_calls и соответствующие tool replies удаляются вместе; незавершённые
   batches не затрагиваются. Последняя пачка остаётся, если помещается.
3. Перед удалением создаётся неизменяемый research_transcript с исходными
   сообщениями. Сводка содержит точные выдержки результатов, вопрос, ошибки,
   ссылки на отчёты и следующий шаг. Она не объявляет модельную интерпретацию
   или наблюдение анализатора независимой метрикой качества.
4. Упакованная история используется на следующих ходах того же диалога.
   Старые исходники не возвращаются автоматически. Текущая обратная связь
   передаётся один раз за запрос и не накапливается в истории как дубликаты.
5. Даже одна слишком большая параллельная пачка может быть архивирована:
   её исходники и ответы остаются доступны отдельно. Читать весь исходный
   запрос ради одного результата не требуется.
6. Если инструментальная схема мешает поместить финальный запрос, Gateway
   сначала закрывает tools и пытается получить настоящее решение модели.
   Controller checkpoint остаётся для действительно несократимого защищённого
   контракта. Он содержит конкретный вопрос и инструкцию чтения сохранённых
   результатов, и больше не считается полученным решением модели в telemetry.

Точные активные архивы читаются через read_memory по выданному reference_id:
transcript_index, tool/CALL_ID/result, tool/CALL_ID/arguments. Для полной истории
есть updates. Доступ проверяет принадлежность к выданному контексту, run/task/
dataset/validation и hash. В новом диалоге доступны архивы видимых поручений,
включая анализы перед ошибкой API без финального решения. Время завершения архива
проверяется по fork cut, как время анализа. Навигация: transcripts_index и
transcript/ARTIFACT_ID/... в frozen details.
Произвольные файлы, SQLite и чужие ветки этим интерфейсом не открываются.

Сервисный кеш результатов остаётся независимым от истории сообщений. Повторный
run_analysis возвращает прежний отчёт, а не требует повторного вычисления после
удаления старого tool turn.

## Время финального ответа

Один 502 на девятом ходе раньше приводил к паузе около 159 секунд и исчерпанию
оставшегося диалога. Backoff теперь считает последовательные транспортные ошибки:
1/2/4/8 секунд с ограничением оставшимся временем. Успешный ответ сбрасывает
счётчик; ожидание не удерживает LLM concurrency slot. Финальные API/token и wall
резервы сохраняются. Доступность провайдера и выдача корректного JSON не гарантируются.

## Настройки и границы

Увеличивать окно ради работоспособности этого механизма не обязательно: регрессии
проверяют прежний предел 98 304 байта. Настройки пользователя поддерживаются:

```dotenv
GRAPH_CONTEXT_BYTES=196608
LLM_REQUEST_MAX_BYTES=196608
```

Настройки читаются при новом запуске. Итоговый предел — минимум локального,
графового, выданного в поручении и защитного расчёта по предполагаемому окну
провайдера. Байты не являются измерением токенизатора. Исходные задачи и ограничения
не обрезаются ради успешной отправки: физически слишком большой обязательный
контракт по-прежнему получает явный диагностический исход.

Изменение не затрагивает выбор моделей, лимит trials, split, метрики или публикацию
CSV. Это исправление исполнения исследования; рост ML-качества требует отдельного
измерения. Синтетические тесты не заменяют live-прогон Qwen.

Фактические проверки и ограничения записаны в validation-context-continuation.json.
