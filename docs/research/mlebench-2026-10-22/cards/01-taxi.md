# 01. Такси Нью-Йорка: геометрия поездки и проверка аномалий

**MLE-bench:** `new-york-city-taxi-fare-prediction`. **Задача:** стоимость поездки, RMSE. **Данные исходного соревнования:** координаты начала/конца, время посадки, число пассажиров; большая обучающая таблица. **Приоритет:** высокий при наличии координат или календарных признаков.

## Два первоисточника

1. **TAXI-1 — Albert van Breemen, [NYC Taxi Fare — Data Exploration](https://www.kaggle.com/code/breemen/nyc-taxi-fare-data-exploration).** Прочитаны пояснения и код. Автор сообщает о временном первом месте 7 августа 2018 года с RMSE 2,88396, полученном отдельной моделью по выводам анализа. Сама опубликованная простая модель такого результата не показывает. Полезное: сначала небольшая часть большой таблицы; зависимости цены от направления, времени и мест посадки; отдельная проверка неправдоподобных координат. Часть анализа использует внешние карты.
2. **TAXI-2 — Luke M, [NYC Taxi Fares — EDA + Modelling (2.93)](https://www.kaggle.com/code/deepdivelm/nyc-taxi-fares-eda-modelling-2-93).** Прочитаны код и выводы; у записи показан результат 2,92883, итоговое место не установлено. LightGBM с пространственными и временными признаками дополнен небольшой долей ближайших соседей. Автор исправляет переставленные координаты и показывает, почему необычные короткие поездки не следует все удалять. Есть признак поправки расстояния по средней цене направления.

## Приём: геометрия вместо четырёх несвязанных столбцов

**Если:** словарь данных подтверждает пары широта/долгота. **Адаптация для нас:**

1. Проверить единицы и допустимые пределы координат. Исправлять перестановку осей только при однозначном подтверждении; иначе отметить сомнительную запись отдельным признаком.
2. Добавить расстояние по сфере, разности координат, направление и его синус/косинус. Для локальной области можно проверить расстояние по двум осям. Не смешивать градусы с метрами.
3. Разложить время на час, день недели, месяц, год. Для циклов использовать период 24, 7 и подходящий календарю годовой период; формулу недели из чужой записи не копировать без проверки.
4. Сравнить с той же моделью без этих признаков. Направление помогает лишь при пространственной структуре задачи; наличие координат само по себе не гарантирует прирост.

## Приём: проверять аномалии по причине, а смесь — по ошибкам

Отрицательная физически невозможная цена и высокая цена короткой поездки — разные случаи. Правила удаления выводить из условия и обучающих данных; не удалять необычные проверочные строки, для которых нужен прогноз. Сначала сравнить вариант без удаления с консервативной очисткой.

Небольшую долю модели ближайших соседей добавлять лишь при улучшении на отложенных строках. Грубая сетка весов достаточна; веса 94/6 из источника не универсальны. Поправку расстояния, использующую цену, считать как кодирование целевой переменной: для обучающих строк — по другим частям обучения, для проверки — только по обучению. Иначе оценка становится завышенной.

## Перенос к нам

- Достаточно одной таблицы с координатами и временем. Карты дорог, маски воды, погода и координаты аэропортов из внешнего справочника не входят в вариант. При необходимости пространственные центры получить из обучающей выборки.
- Допустимы NumPy, pandas, scikit-learn, LightGBM. `pandas_profiling` из исходной записи не нужен.
- На десятках миллионов строк начинать с воспроизводимой выборки, а не первых строк файла; проверочную часть держать неизменной. Ближайшие соседи на полном объёме могут оказаться слишком дорогими.

**Первый опыт:** ограничить исследование 20 минутами: исходный LightGBM → геометрия/календарь → одна проверка очистки. Записать RMSE, время подготовки и обучения, максимум памяти. Смесь проверять следующим опытом только при достаточном запасе времени.
