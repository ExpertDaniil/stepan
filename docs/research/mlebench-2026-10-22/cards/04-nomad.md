# 04. NOMAD: физические инварианты и связь нескольких целей

**MLE-bench:** `nomad2018-predict-transparent-conductors`. **Задача:** две физические характеристики материала; средняя по целям RMSLE. **Исходные входы:** небольшая таблица и отдельные текстовые файлы с решёткой/атомами. **Приоритет:** высокий для малых физических таблиц; геометрическая часть условна.

## Три первоисточника

1. **NOMAD-1 — Christopher Sutton и соавторы, [NOMAD 2018 Kaggle Competition: Solving Materials Science Challenges Through Crowd Sourcing](https://arxiv.org/abs/1812.00085).** Совместная статья организаторов и призёров; прочитаны сопоставление результатов и разделы методов I–III в полном тексте. Победитель считает короткие цепочки типов атомных окружений в графе кристалла, нормирует частоты на объём и применяет KernelRidge. Второе место отбирает компактное подмножество физических признаков для LightGBM; часть этих признаков использует внешние справочные свойства элементов. Третье сочетает описание окружения атомов с нейросетью.
2. **NOMAD-2 — Christian Spethmann, [9th place solution with geometric features](https://www.kaggle.com/competitions/nomad2018-predict-transparent-conductors/writeups/christian-spethmann-9th-place-solution-with-geomet).** Разбор прочитан целиком; девятое итоговое место. Радиальные и угловые распределения стали признаками для XGBoost. Прогноз более простой цели использован при предсказании второй. Попытка недорогих прямых физических расчётов не дала нужной точности.
3. **NOMAD-3 — alabatie, [исходное решение NOMAD](https://github.com/alabatie/nomad).** Прочитан подробный README. Представление плотности атомов с учётом периодичности, PCA и ядерные модели оказались лучше и дешевле собственной трёхмерной нейросети автора. Заявлены лучшие 1% публичной таблицы; итоговое место не подтверждено.

## Приём: кодировать свойства объекта, а не произвольную систему координат

**Если:** есть физические размеры, состав, плотности либо координаты частей объекта. **Адаптация для нас:** сначала признаки из основной таблицы — доли компонентов, отношения, объём из согласованных размеров, нормирование на число элементов. Проверить единицы и допустимые области. Простое произведение трёх длин не равно объёму произвольной наклонной ячейки: нужны углы или определитель матрицы решётки.

При наличии выданной геометрии — распределения расстояний по типам атомов, компактные угловые сводки, периодические соседства. Если выдан также граф связей, можно проверить частоты коротких цепочек типов окружений вместо дорогой графовой сети. Учитывать границы ячейки, не трактовать атомы на противоположных границах как далёкие. При отсутствии геометрии этот шаг пропускается.

На небольшой выборке сравнить стандартизованный SVR/KernelRidge с бустингом. PCA обучать внутри обучающей части. Полное квадратичное ядро плохо переносится на очень большие таблицы; этот вариант именно для малого числа объектов.

## Приём: связать прогнозы нескольких целей без подсматривания

Если одна цель помогает другой, получить прогноз первой для обучающих строк по разбиениям, в которых эти строки не участвовали в обучении. Передать эти прогнозы второй модели; на независимой проверке использовать первую модель, обученную только на обучении. При внутренней настройке всей цепочки обе ступени переобучать внутри соответствующего разбиения. Это наша защита от утечки, не утверждение о деталях проверки NOMAD-2.

Проверить независимые модели против цепочки. Для RMSLE использовать `log1p` только при допустимой области целей и обратное преобразование при выдаче. Не делать такой вывод для произвольной другой метрики или отрицательных целей.

## Перенос к нам

В табличном варианте достаточно основной CSV и NumPy/SciPy/scikit-learn/бустинга. Геометрия требует действительно предоставленных файлов; ASE, GPAW, QUIPPY, внешние справочники свойств элементов и новые физические расчёты не используются. Плотные трёхмерные кубы, готовые атомные описатели и чужие веса не нужны для первого опыта.

**Первый опыт:** до 20 минут на смысловые физические признаки и сравнение одной ядерной модели с бустингом. Цепочку целей исследовать отдельно, если условие вообще содержит несколько целей. Фиксировать ошибку каждой цели, их итоговое среднее и затраты подготовки.
