# Локальное сравнение A/B

Ветка `test` основана на `feat/final-data-research` (`fa25a30`). Это стенд для
локальных запусков, не ZIP для лидерборда. Production-модули не изменены.

## Что сравниваем

| Режим | Поведение |
|---|---|
| A | Тот же baseline, четыре каталожных warmup и VersionSearch/Optuna. Исследователи возвращают явный stop. API-вызовы запрещены дополнительной проверкой. |
| B | Тот же старт и фоновый поиск плюс обычный исследовательский цикл LLM. |

Контракт задачи задаётся явно через target/kind/metric/id. Оба запуска получают
одинаковую inner-валидацию и неизвестную семантическую модель. Вызовы интерпретатора
задачи и выбора валидации заменены только в benchmark child. Это **контролируемое
сравнение исследовательского цикла**, не полный тест автономного bootstrap.
Оригинальный текст задачи и словарь признаков остаются доступны исследователю B.

У A и B одинаковые OOF/каталог/бюджеты и снимок исходников. Меняется только выдача
исследовательских предложений. Это проверка суммарной пользы LLM-исследования;
отдельный эффект конкретного признака или анализа ошибок она не доказывает.

## Подготовка

Linux или WSL2, Python 3.12. Из корня репозитория:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.runtime.txt
```

Это существующий закреплённый development subset разрешённых библиотек. Для
сопоставимости с платформой используйте её полную подготовленную среду, если она
доступна. Доступные пакеты ограничивают, какие предложения B удастся обучить.
Во время самих запусков ничего не устанавливается.

Данные распакуйте отдельно, `.env` с предоставленными OPENAI_API_KEY,
OPENAI_BASE_URL и OPENAI_MODEL оставьте локально. Ключ не передавайте в аргументах
команд и не коммитьте. Файл `.env` читается только при явном `--env-file`.

## Регрессия: два запуска по 30 минут

```bash
python scripts/ab_benchmark.py run \
  --task "data_for_participants/Регрессия/task.md" \
  --target site_eui --id-column id --kind regression --metric rmse \
  --env-file .env \
  --seconds 1800 --checkpoints 300,900,1800 \
  --out runs/ab-regression-seed42
```

## Классификация

```bash
python scripts/ab_benchmark.py run \
  --task "data_for_participants/Многоклассовая классификация/task.md" \
  --target attack_cat --id-column id --kind classification --metric f1_macro \
  --env-file .env \
  --seconds 1800 --checkpoints 300,900,1800 \
  --out runs/ab-classification-seed42
```

Пути и имена колонок здесь — явные аргументы стенда. Агент не получает
датасет-специфичных ветвлений. Для другой задачи укажите её target/id/metric.
Если уникального ID нет, опустите `--id-column`: стенд добавит исключённый из
признаков технический ID. Сейчас поддержан один таргет, регрессия и классификация
с выдачей меток. Групповые/временные задачи требуют другого outer split; этот
стенд использует random split, stratified для классификации.

A и B выполняются **последовательно**, каждый до 30 минут плюс аварийный запас
родителя 60 секунд. Весь опыт — около часа на одну задачу. Часы каждого child
включают профилирование, warmup, исследования, refit и финальную проверку.
Фактические ресурсы ограничиваются существующим execution_capacity (до 8 CPU с
учётом analysis, резерв памяти относительно доступной/cgroup RAM).

Старые локальные `LLM_MAX_CALLS`, `TIME_BUDGET_SECONDS` и прочие agent-настройки
из окружения/`.env` очищаются: одинаковые параметры берутся из platform defaults
и аргументов стенда. OPENAI-параметры сохраняются; лимит calls/output общий не
вводится. B использует платный предоставленный API. A и probe его не вызывают.

Для проверки порядка/cache эффекта повторите с `--order B,A --seed 43` и новым
`--out`. Сравнение одной пары не является статистически надёжным доказательством.

## Где результаты

В указанном `--out`:

- `report.md`: таблица A/B на 5/15/30 минутах, статусы и итоговые сырые метрики.
- `report.json`: оценки, история обучений, параметры, счётчики событий, ошибки,
  последнее состояние токенов и измеренное время API/worker.
- `protocol.json`: seed, размеры, hashes одинаковых данных, версия исходников,
  версии пакетов и параметры опыта; секретов нет.
- `A/terminal.log`, `B/terminal.log` и `A/runs/`, `B/runs/`: исходные логи агента.
- `A/publications/`, `B/publications/`: неизменяемая копия каждого опубликованного
  CSV и момент его готовности. Исходники кандидатов остаются в run-артефактах.
- `private/`: outer labels и индексы разбиения; child не получает их пути/файлы.

20% размеченного train по умолчанию откладывается в outer audit. В `train.csv`
агента этих строк нет, в его `test.csv` есть только их признаки. Исходный
публичный test.csv вообще не используется. Оба режима видят одинаковые train,
test, sample, текст, словарь и frozen contract. Private-файлы находятся вне task
root и не передаются ни в контексты LLM, ни в инструменты анализа.

Оценки outer audit вычисляются **после завершения обоих запусков**, без обратной
связи агенту. Для отметки 300 секунд берётся последний уже опубликованный CSV
не позднее 300 секунд. Будущий победитель не подставляется задним числом.
Если к отметке CSV не было, пишется unavailable. Если процесс завершился раньше,
его последний готовый ответ остаётся доступным на последующих отметках.

Финальный CSV может отличаться от последней отметки из-за confirmation/refit.
30-минутный запуск имеет собственный финальный резерв и не равен первым
30 минутам трёхчасового запуска. Для длинного опыта задайте, например,
`--seconds 10800 --checkpoints 300,900,1800,3600,7200,10800`.

`api_pending_without_worker_seconds` — объединённое время, когда API-запросы
ожидались, а train/refit/OOF jobs не были активны. Это не замер загрузки CPU.
Суммы длительностей перекрывающихся jobs/API отдельно помечены как суммы.
Итоговое состояние читается из SQLite после остановки процесса. Если в журнале
нет `run.finished`, отчёт явно предупреждает, что счётчики/тайминги событий
могут быть неполными; отсутствие строки лога не подменяется успехом по exit=0.

Повторно построить отчёт без API и обучения:

```bash
python scripts/ab_benchmark.py report runs/ab-regression-seed42
```

Прошлые результаты не перезаписываются. Повторный опыт требует новый `--out`.
Прерванный запуск не возобновляется автоматически. Не отправляйте каталог
результатов целиком в git: в нём данные и подробные выводы модели.

## Тест раннего таймаута

```bash
python scripts/ab_benchmark.py probe --out runs/bootstrap-timeout-probe
```

Probe создаёт новую синтетическую задачу и подменяет транспорт LLM на TimeoutError
до первого ответа. Сеть не вызывается; реальные ключи не нужны. Результат —
`runs/bootstrap-timeout-probe/result/probe.json` и логи рядом.

Текущая версия воспроизводит уязвимость: `protected_against_startup_timeout=false`,
нет CSV, exit агента 1. Сам probe возвращает **2**, чтобы проблема была заметна
в терминале/CI. Это ожидаемый отрицательный результат, а не ошибка стенда.
Код 0 будет означать, что ранняя защита действительно сформировала CSV.
Production bootstrap/fallback эта ветка не исправляет и не маскирует.

## Быстрая проверка стенда без API

```bash
python -m unittest tests.test_ab_benchmark tests.test_packaging -q
python scripts/ab_benchmark.py run --kind regression --demo --mock \
  --seconds 45 --checkpoints 5,15,45 --out runs/ab-smoke-regression
python scripts/ab_benchmark.py run --kind classification --demo --mock \
  --seconds 45 --checkpoints 5,15,45 --out runs/ab-smoke-classification
```

`--mock` проверяет провода стенда с настоящими fit/evaluate/refit, а не качество
автономного Qwen. Вызовы из live-опыта здесь не запускались. Нормированные баллы
лидерборда стенд не вычисляет: неизвестны его скрытые ответы и baseline-метрики.

## Проверка этой ветки

- Python 3.12.14, закреплённый `requirements.runtime.txt`.
- `tests.test_ab_benchmark` + `tests.test_packaging`: 14 тестов OK.
- По два 45-секундных A/B запуска на синтетических regression/classification:
  все четыре процесса завершились с exit=0, SQLite state=completed и CSV.
- Повторный сквозной CLI после правки чтения persisted state: оба режима
  завершились с exit=0 на 15-секундном синтетическом regression опыте.
- Таймаут-тест: воспроизведены agent exit=1, отсутствие CSV и probe exit=2;
  сетевых вызовов 0.
- В контрольном A — 0 API calls. В B mock реально прошли исследовательские
  предложения и обучение. Это проверка исполнения, не выигрыш качества Qwen.
- Compileall и git diff --check пройдены. Полный исторический suite репозитория
  для этих изолированных scripts не перезапускался.
