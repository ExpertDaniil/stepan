# 05. CHAMPS: связанные таблицы, соседства и метрика по типам

**MLE-bench:** `champs-scalar-coupling`. **Задача:** взаимодействие пары атомов. **Метрика:** среднее логарифмов MAE, отдельно посчитанных по типам взаимодействия. **Исходные входы:** таблица пар и таблица атомов с координатами. **Приоритет:** средний; геометрия условна, работа с ключами переносится шире.

## Три первоисточника

1. **CHAMPS-1 — Zico Kolter и команда hybrid, [#1 Solution — hybrid](https://www.kaggle.com/competitions/champs-scalar-coupling/writeups/hybrid-1-solution-hybrid).** Прочитан авторский разбор первого места. В основе — расстояния, структура молекулы и отдельные выходы для подтипов связей. Расстояния дают инвариантность к повороту. Окончательная смесь из 13 больших моделей обучалась на многочисленных видеокартах. Дополнительные датасеты QM7/QM9 не использовались.
2. **CHAMPS-2 — Bosch Research, [BCAI_kaggle_CHAMPS](https://github.com/boschresearch/BCAI_kaggle_CHAMPS).** Прочитаны описание воспроизведения и требования. Это код той же победной команды, не второе независимое решение. Он подтверждает большой расход ресурсов и использование специальных зависимостей; прямое воспроизведение нам не подходит.
3. **CHAMPS-3 — Ashesh., [62nd Place Solution](https://www.kaggle.com/competitions/champs-scalar-coupling/writeups/ashesh-62nd-place-solution).** Разбор прочитан целиком. Соседства по расстояниям, геометрические агрегаты и углы использованы в CatBoost/LightGBM; автор отдельно описывает ускорение вычислений средствами NumPy. Выбрано ради более доступной табличной ветки. Результат команды не равен результату одного бустинга, а исходные химические признаки частично требуют OpenBabel.

## Приём: сначала восстановить объект из таблиц

**Если:** строки описывают отношения между объектами, а свойства самих объектов лежат в другой выданной таблице. **Адаптация для нас:**

1. Найти составной ключ. Здесь это молекула и номер атома: один номер атома не уникален между молекулами.
2. Дважды присоединить свойства — для первого и второго участника пары. Проверить уникальность ключей, число строк до/после соединения и долю отсутствующих соответствий.
3. Рассчитать расстояния и компактные сводки ближайших соседей внутри одного объекта. Геометрический сосед не обязательно означает химическую связь: не присваивать ему такой смысл без данных.
4. Матрицу расстояний строить отдельно для каждой молекулы/группы. Глобальная матрица всех строк растёт квадратично и не нужна.

## Приём: специализация по типам и правильная оценка

Сравнить общую модель с признаком типа и отдельные модели для достаточно больших типов. Малые типы оставить общей модели. В CHAMPS геометрия и распределения целей существенно различаются по типам, поэтому единая общая RMSE плохо отражает нужное улучшение.

Рассчитывать `mean_t(log(max(MAE_t, eps)))`, если именно это определено условием; логарифм здесь применяется к ошибке группы, а не к самой целевой переменной. Проверять наличие всех типов на проверке. В задачах на новые молекулы/клиентов/устройства разделять обучение и проверку целыми объектами, иначе общая структура объекта просачивается в оценку.

## Перенос к нам

- `structures.csv` и другие дополнительные таблицы должны быть выданы в текущей задаче. Из обычного `train.csv` с парами без координат восстановить геометрию нельзя. Для четырёх стандартных CSV переносимая часть ограничивается уже имеющимися групповыми и парными признаками.
- NumPy/SciPy, pandas/Polars и бустинги достаточны для геометрического приближения. RDKit, OpenBabel, PyTorch Geometric, APEX и готовые веса исключены.
- У MLE-bench известна проблема отсутствующей геометрии части проверочных молекул: до опыта проверить покрытие соединений; не заменять пропавшие структуры внешним набором. Источник проблемы — официальный README MLE-bench, указанный в оглавлении.

**Первый опыт:** до 25 минут на аудит ключей, расстояния/сводки и одну общую модель. Затем один вариант специализации. Сохранить ошибку каждого типа, итоговую метрику, долю пропавших соединений и время подготовки. Полную победную архитектуру в этот опыт не включать.
