## Состав и соответствие исходникам

Платформенный ZIP содержит 41 корневой файл: `solution.py`, официальный
`requirements.txt`, 38 отдельных Python-модулей и `stepan_resources.py`.
Каждый модуль побайтово совпадает с соответствующим исходником дерева сборки.
Например, `agent/graph/controller.py` сохранён как `agent_graph_controller.py`.
Тест проверяет все 38 файлов, включая граф, Gateway, Runner, worker и tools.

В `stepan_resources.py` находятся 13 открытых текстовых ресурсов — SQL,
JSON, Markdown и lock списка зависимостей. AST/literal_eval-проверка подтверждает
точное восстановление всех исходных байтов. Непрозрачных строк с Python-кодом,
base64/base85 и встроенного runtime-архива в точке входа нет.

`solution.py` содержит 89 строк, включая явное соответствие имён файлов.
Он копирует соседние исходники в обычные package-каталоги под `/tmp`, записывает
текстовые ресурсы и вызывает `agent.runtime.main`. Поэтому обычные импорты,
subprocess worker и сохранение собственного runtime для реконструкции графа
продолжают использовать исходную структуру пакетов без переписывания модулей.

Повторная сборка даёт те же байты. requirements.txt побайтово равен исходному
списку организаторов. Внешние пакеты, CSV, модели, ключи, .env и журналы в ZIP
не входят. Проверены синтаксис всех Python-файлов, целостность ZIP, плоские имена
и сохранение предыдущего архива при неудачной сборке.

## Запуск

Для классификации и регрессии проверен запуск ровно `python solution.py task.md`
из каталога синтетической задачи после копирования только корневых `.py` и
`requirements.txt`. Исходного agent/ рядом нет; PYTHONPATH репозитория удалён.
Каждый запуск создаёт корректный CSV рядом с условием, проходит обучение,
исследование, оценку, refit и публикацию. Mock используется только как API transport;
обучение, метрики и CSV настоящие. По умолчанию платформенный код остаётся live.

Общий прогон также покрывает граф, изоляцию контекстов, перенос, fork/backtrack,
транзакции, recovery, воспроизведение предсказаний, ограничения процессов и все
исходные проверки v0.3.1. Логика ML и Research Graph сохранена из основы.

## Обработка предоставленного отказа API

Внешний лог классификации от 21 октября, около 22:43 МСК, показывает HTTP 503
с `OpenrouterException - Insufficient credits` на C02/C10. До обучения запуск
не дошёл. Gateway теперь распознаёт этот маркер как
`LLM_PROVIDER_CREDITS_EXHAUSTED`, прекращает повторы и следующие API-вызовы
в текущем запуске. Остаток командного бюджета и время сброса остаются unknown.
Автоматической смены endpoint или перехода в mock нет.

Проверены маркер в тексте исключения и вложенном error body, отсутствие retry,
блокировка повторного обращения, обычный временный 503 с retry и честный отказ
до bootstrap без выдуманного CSV. Исходные правила Budget has been exceeded
и сохранения уже опубликованного результата продолжают проходить проверки.
Эта правка улучшает обработку отказа; доступ к провайдеру восстанавливает оператор API.
