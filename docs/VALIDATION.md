## Следующий внешний прогон команды

1. Для локального прогона установить requirements.runtime.txt в чистую Python 3.12 среду или собрать Dockerfile. Точный официальный список requirements.txt отдельно проверяется в предоставленной среде платформы.
2. Запустить scripts/doctor.py и scripts/check.py на точных версиях.
3. Подключить значения OPENAI_* организаторов и проверить один небольшой live-запуск, включая JSON/tool-call формат конкретного сервиса.
4. Проверить CatBoost-рецепт и интерфейс официального контейнера.
5. После этого отправлять dist/solution.zip на платформу с учётом лимита сабмитов.

Live API, точный Docker-образ платформы и CatBoost фактически не запускались: ключ отсутствует, необходимые пакеты не установлены. Адреса прокси и модель теперь известны из инструкции; доступность сети/поведение live-сервиса не проверялись. Полный официальный requirements.txt побайтово сохранён, но его установка и совместимость всех пакетов здесь не подтверждены. Приложенный Dockerfile — подготовленная конфигурация локального прогона, а не утверждение о выполненной Docker-сборке. Это рабочий каркас для развития командой, не заявление о готовом соревновательном качестве.

## Дополнительные проверки v0.3.1

- Реальный worker с exit code 0, success=true и живым дочерним процессом: очистка группы,
  сохранение succeeded, C15 и C13 release без C24 cancellation. До исправления тест воспроизводил cancelled.
- Exit code 1, success=false и отсутствие result.json по-прежнему дают failed после очистки.
- Ошибка остановки группы не освобождает lease и не сообщает о завершении задания.

  NSpid и namespace identity связывают локальные PID с фактическими путями /proc.
- Полный синтетический регрессионный цикл специально оставляет helper после каждого refit.
  Проходят warmup, LLM-mock исследователи, проверки кандидатов и минимум две публикации;
  запуск завершается completed. Остальные subprocess- и flat-ZIP проверки также прошли.
