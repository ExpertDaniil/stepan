# Поиск по доступному времени · v0.5.0

Поиск не завершается по счётчику обучений, исчерпанию обращений к модели или её ответу «достаточно».
Новый запуск допускается, когда его прогнозируемое время вместе с запасом на окончательное обучение
и сохранение ответа помещается в оставшееся время. При отсутствии доступного нового кандидата
поиск завершается раньше общего срока; в графе сначала проверяются сохранённые альтернативные ветви.

## Связанные испытания

`RESEARCH_SERIES_SIZE=4` задаёт исходный вариант и до трёх соседних конфигураций. Серия привязана
к исследователю и ветви и хранит небольшую очередь параметров. Отдельной системы гипотез нет.
Обычно меняется один параметр: числовое значение в допустимых границах либо вариант перечисления.
Оценку считает прежний независимый оценщик на неизменном протоколе проверки.

Между сериями оркестратор получает новое предложение модели. Если квота обращений или выходных
токенов исчерпана либо сервис недоступен, он продолжает выбирать варианты из проверенного каталога:
чередует окружение собственной базы с менее изученными семействами. После ближайших вариантов
доступен воспроизводимый подбор отдельных параметров с тем же начальным числом генератора.

Повторные конфигурации каталога, включая ранее неудавшиеся обучения, пропускаются. Недопустимый
ответ модели записывается как ошибка, затем заменяется локальным предложением. Ошибка обучения
не останавливает следующие связанные испытания. Все локальные планы проходят прежние проверки
параметров, кода, происхождения и ограничений ветви. Локально используется только собственный код каталога.

## Прогноз длительности

`agent/duration.py` хранит до 32 последних измерений на семейство в текущем запуске. Время процесса
разделяется на обучение и прочие затраты, если worker сообщил `fit_seconds`. Прогноз использует
75-й процентиль нормированной стоимости обучения и наблюдаемые накладные расходы с запасом 35%.

Масштаб учитывает число обучающих строк, признаков и потоков, включённые числовые взаимодействия,
а также основные параметры семейства:

| Семейство | Параметры стоимости |
|---|---|
| CatBoost | число итераций и глубина |
| HistGradientBoosting | число итераций и листьев |
| RandomForest / ExtraTrees | число деревьев, глубина, размер листа и доля признаков |
| Линейные модели | размер данных; для классификации — приближённое влияние `C` на сходимость |

Пока истории семейства нет, используется ограниченная начальная оценка; она не заимствует
скорость другого семейства. Начальная оценка отдельно сохраняет время запуска процесса и импортов,
которое не уменьшается пропорционально числу деревьев. Прерывание по времени даёт нижнюю границу стоимости, а не короткое
успешное обучение. Прогноз остаётся приближением: он не учитывает все особенности данных и
планировщика операционной системы. Между задачами история не переносится.

## Запас на готовый ответ

Перед обучением резервируется максимум из стоимости итогового обучения текущего ещё не
опубликованного лучшего кандидата и нового кандидата, плюс время сохранения результата.
Полное обучение прогнозируется с числом строк всей обучающей таблицы. Активные задания также
участвуют в резерве. Для сохранения остаётся 3% общего времени, от 2 до 60 секунд.
Прежнего ограничения резерва долей 35% нет: тяжёлое итоговое обучение может требовать больше.

Проверка повторяется непосредственно при выдаче ресурсов. Если время истекло между выбором
и запуском, задание отменяется штатно. Прогноз обновляется по завершении процесса. Когда лучший
кандидат уже опубликован, повторный запас на обучение именно этой модели больше не удерживается.
При недостатке времени на новый полный ответ прежний проверенный CSV сохраняется.

`MAX_RESEARCH_EXPERIMENTS` оставлен в разборе старых настроек и не влияет на остановку.
`LLM_MAX_CALLS` и `LLM_MAX_TOTAL_OUTPUT_TOKENS` продолжают ограничивать обращения к сервису.
Начальные испытания ограничены `CATALOG_WARMUP_EXPERIMENTS`, затем действует общий поиск по времени.

## Проверка

`tests/test_time_search.py` проверяет масштабирование оценок, резерв полного обучения,
прерывания по времени, отказ у границы выдачи ресурсов, ограничения ветвей и пропуск повторов.
Сквозные сценарии обучают реальные линейные модели на синтетических данных: более 12 запусков,
исчерпание квоты API, повторное предложение и единичный отказ запуска процесса. Сервис модели
в них заменён; результаты этих проверок не подтверждают улучшение метрики на задачах соревнования.

22 октября 2026 года после совмещения с `ab6b577` выполнен полный `python3 scripts/check.py`:
**175 тестов, 559,641 секунды, успешно**. Среда — Ubuntu 24.04 через WSL, Python 3.12.3;
проверка включает новые проверки баз ветвей, плато, ограничений сохранённых моделей и плоской поставки.
Контрольные сценарии обучались на синтетических данных; настоящий сервис модели, задачи соревнования
и непрерывный трёхчасовой запуск не проверялись. Список зависимостей организаторов не менялся.

В v0.5.1 холодный прогноз использует измеренные расходы запуска Dummy как нижнюю границу
общей загрузки Python/данных с запасом, а не фиксированные две секунды. Для известного семейства
расходы вне fit оцениваются по верхнему квартилю и последнему наблюдению. Сама стоимость fit
по-прежнему переносится только внутри семейства. Это уменьшает риск позднего запуска с короткой lease.
